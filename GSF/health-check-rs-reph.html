Cấu hình instance — đã được tune tốt

16 core / 64 GB / 2 NUMA. max memory = 48 GB, MAXDOP = 8, cost threshold = 50, optimize for ad hoc = 1, page verify = CHECKSUM, auto-stats bật. Chỉ nên bật thêm backup compression default.

Root cause I/O-bound: thiếu nonclustered index

Các bảng khổng lồ chỉ có clustered PK, hoàn toàn không có nonclustered index phục vụ report: SESSIONDISHES (104M dòng, 47 GB), OPERATIONLOG (154M, 19 GB), TAXPARTS (100M), PAYBINDINGS (100M), UploadHistory (64M), DISCPARTS (50M), ORDERSESSIONS (48M), VISITGUESTS (22M). Bộ proc SP_SAP_Reconciliation + SP_GetTaxTotal/SaleTotal/PaymentTotal/DiscTotal lọc theo (@IRESTAURANT, @START_DATE, @END_DATE) nhưng phải scan full → mỗi lần đọc ~2.8 triệu page (~22 GB logical I/O), chạy hàng chục nghìn lần/ngày. Đây là nguyên nhân trực tiếp của CXPACKET 54% + PAGEIOLATCH_SH trong wait stats.

5 bảng HEAP lớn (không có clustered index)

CRM_CARD_TRANSACTIONS (16M dòng, 2.5 GB heap), DATA_RK7_AG_SERVICE_LOG_DETAILS (14.7M), CRM_CARD_TRANSACTION_NOTE (5M), STAT_RK7_SHIFTS_CECKSUM (5M / 6.5 GB), DATA_RK7_AG_SERVICE_LOG (4.9M / 6.4 GB). Heap scan kém hiệu quả và dễ sinh forwarded record.

Fill factor 80 sai hướng cho workload đọc

Sau reindex, fragmentation ~0% (job hoạt động tốt) nhưng clustered index chỉ đầy ~80%/trang → lãng phí ~20% dung lượng và đọc dư 20% page trên mỗi scan. Với bảng insert-rồi-đọc như reporting, nên dùng fillfactor 95–100 để giảm I/O ngay lập tức.

Storage & dung lượng file

RS_REPH: 321 GB cấp phát, thực dùng 168 GB (còn 153 GB trống trong file — dư headroom). Tất cả data/log/tempdb nằm chung ổ D:\ (70.8%). DB RK7BK20182021 (backup 2018–2021 "không xóa") đang online chiếm 321 GB.

Backup — lỗ hổng ở các DB FULL recovery

RS_REPH và STAT DBs được backup full hằng đêm (OK). Nhưng ShiftTransport (FULL, chưa backup log → log đã 4.26 GB), ReportServer / DWConfiguration / Skymonitor (FULL, chưa từng backup) → log không truncate được + không có điểm phục hồi.

Phương án tối ưu (ưu tiên theo tác động)
🔴 P0 — Tác động lớn nhất, làm sớm off-peak · test trên dcorpcrmtest
  • Thêm nonclustered index cho các query report nặng nhất — đòn bẩy #1, biến scan 100M dòng thành seek. Tạo ONLINE = ON (Enterprise hỗ trợ, không khóa bảng).
-- GLOBALSHIFTS: 275K seek, impact 97.8% — cao nhất
CREATE NONCLUSTERED INDEX IX_GLOBALSHIFTS_GUIDSTRING_STATUS
ON dbo.GLOBALSHIFTS (GUIDSTRING, STATUS)
WITH (ONLINE=ON, FILLFACTOR=100, SORT_IN_TEMPDB=ON, MAXDOP=4);

-- SESSIONDISHES: bảng lớn nhất, scan theo ngày trong report
CREATE NONCLUSTERED INDEX IX_SESSIONDISHES_CREATIONDATETIME
ON dbo.SESSIONDISHES (CREATIONDATETIME)
INCLUDE (VISIT, MIDSERVER, UNI)
WITH (ONLINE=ON, FILLFACTOR=100, SORT_IN_TEMPDB=ON, MAXDOP=4);

-- CRM_CARD_TRANSACTIONS (heap): lọc theo TRANSACTION_TYPE
CREATE NONCLUSTERED INDEX IX_CRMCT_TYPE
ON dbo.CRM_CARD_TRANSACTIONS (TRANSACTION_TYPE)
INCLUDE (TRANSACTION_ID, TRANSACTION_TIME, ACCOUNT_ID, SUMM, EXTERNAL_ID)
WITH (ONLINE=ON, FILLFACTOR=100, SORT_IN_TEMPDB=ON, MAXDOP=4);
  • Sửa fill factor về 95–100 cho các bảng report insert-rồi-đọc → giảm ~20% size + I/O ngay, nâng PLE hiệu dụng.
ALTER INDEX PK_SESSIONDISHES ON dbo.SESSIONDISHES
REBUILD WITH (ONLINE=ON, FILLFACTOR=100, SORT_IN_TEMPDB=ON, MAXDOP=4);
-- áp dụng tương tự: OPERATIONLOG, ORDERSESSIONS, TAXPARTS, PAYBINDINGS...
Lưu ý: đây là bảng thuộc hệ RK7 do vendor UCS quản lý — đặt tên index rõ ràng (IX_...) để phân biệt, test trên dcorpcrmtest trước. Trước khi tạo hàng loạt nên phân tích execution plan của SP_SAP_ReconciliationReport + SP_GetTaxTotal để chọn đúng bộ index khớp cả 5–6 proc, tránh tạo thừa.
🟡 P1 — Nên làm trong tuần
  • Chuyển 5 HEAP lớn thành clustered index (CRM_CARD_TRANSACTIONS, DATA_RK7_AG_SERVICE_LOG(_DETAILS), CRM_CARD_TRANSACTION_NOTE, STAT_RK7_SHIFTS_CECKSUM) — chọn clustered key theo cột truy vấn phổ biến (GUID/DATETIME).
  • Vá SQL 2016: RTM có nhiều bug nghiêm trọng đã fix. Tối thiểu lên SP3 + GDR mới nhất. (2016 gần hết extended support 07/2026 — cần kế hoạch nâng đời trung hạn.)
  • Sửa autogrowth 1 MB → 512 MB cho RK7_SAP_RS, POS_INT_EFFECT (đang gây fragmentation vật lý + growth event liên tục).
  • Xử lý backup các DB FULL không backup: ShiftTransport / ReportServer / Skymonitor / DWConfiguration — hoặc chuyển SIMPLE (nếu không cần point-in-time), hoặc thêm log backup, tránh log phình.
🟢 P2 — Tối ưu dài hạn
  • Cân đối tempdb: đưa 8 file về cùng size (ví dụ mỗi file 8 GB).
  • Tối ưu job reindex 9h: chuyển sang script theo ngưỡng fragmentation (reorg 5–30%, rebuild >30%) thay vì rebuild toàn bộ → giảm còn 1–2h.
  • Giải phóng ổ D:\: RK7BK20182021 (321 GB) — cân nhắc detach + nén lưu offline để lấy lại ~321 GB.
  • Bật backup compression default = 1; review 2 index gần trùng trên PAYBINDINGS.
Rủi ro & rollback: Tạo index ONLINE không khóa bảng nhưng tốn tempdb + I/O — chạy off-peak, giới hạn MAXDOP. Index mới có thể DROP tức thì để rollback. Rebuild fillfactor revert được bằng rebuild lại. Mọi thao tác nên test trên dcorpcrmtest trước. Connection health check này là read-only — mọi DDL do DBA thực thi trực tiếp trong SSMS.
