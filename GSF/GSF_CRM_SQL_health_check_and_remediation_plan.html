Phần còn lại của chuỗi (Instant File Initialization vẫn tắt, query CAST vendor chưa sửa) vẫn tồn tại — xem tab "Kế hoạch tiếp theo".
✅ Không phát hiện vấn đề
Tại thời điểm kiểm tra: không có blocking chain, không có transaction mở kéo dài bất thường, scheduler không tồn đọng công việc, memory dư dả (63GB RAM, 49GB available), tempdb cấu hình 8 file đồng đều đúng best practice, config user connections không bị giới hạn cứng.

Trong lúc theo dõi trực tiếp sau khi restart, ring buffer ghi nhận nhiều lần login từ IP 10.10.2.1 bị treo ~380 giây rồi reset — đã xác nhận với anh Hải đây là traffic VPN bình thường của user, không liên quan đến sự cố đang điều tra, không cần xử lý. Riêng 1 lần treo 196.7 giây từ loopback (192.168.62.95) lúc 14:00:34 UTC trùng khớp thời điểm chạy lệnh resize file — nhiều khả năng là hệ quả một lần của thao tác zero-fill I/O, không lặp lại sau đó.

2. Query CAST phá sargable trên CARD_TRANSACTIONS (23 triệu dòng)
CRITICAL
Tính năng tra cứu giao dịch của RKeeper_CRM_Server.exe dùng CAST(TRANSACTION_TIME AS DATETIME) >= CAST(@DateFrom AS DATE) — vì TRANSACTION_TIME là datetimeoffset, phép CAST này không seek được index dù index đúng cột đã tồn tại (I_CARD_TRANSACTIONS_B), buộc scan toàn bộ index mỗi lần tra cứu (~1 triệu logical reads/lần, phiên dài nhất quan sát được chạy 71.7 giây). Đây là code phía vendor RKeeper — không tự sửa được, cần escalate.
Session 147 — RKeeper_CRM_Server.exe: elapsed 71,739ms, reads 1,073,190, wait PAGEIOLATCH_SH Bảng CARD_TRANSACTIONS đã có cột TRANSACTION_TIME_ORIGINAL (datetime thuần) kèm index riêng — có thể dùng thay thế nếu vendor đồng ý sửa
🟡 Mức nghiêm trọng trung bình
3. Thiếu index trên CARD_TRANSACTIONS_SPECIALOFFER(SPECIALOFFER_ID)
ĐÃ XỬ LÝ
Trùng thời điểm với job SQL Agent "Start SP SpecialOffer" đang chạy — SQL Server ước tính thêm index này sẽ cải thiện 97.8% cho các truy vấn liên quan. Impact score cao nhất trong toàn bộ missing index của database. Cập nhật 20/09: đã tạo IX_CARD_TRANSACTIONS_SPECIALOFFER_SpecialOfferID (ONLINE, bảng chỉ 39.5MB nên xong trong vài giây, không downtime).
Equality: [SPECIALOFFER_ID] Include: [TRANSACTION_ID],[ACCOUNT_ID] avg_user_impact: 97.76% user_seeks: 134 → Index đã tạo, is_disabled = False ĐÃ FIX
4. Disk read latency hơi cao trên filegroup CRM_AT
MEDIUM
Avg read latency ~26ms/read trên file CRM_AT (41.5GB), ~16ms/read trên file CRM chính. Chưa ở mức báo động nhưng cao hơn chuẩn SSD/NVMe tốt (lý tưởng <10ms) — cộng dồn với các vấn đề khác góp phần vào cảm giác lag.
