Nhận xét
  • Từ htop SQL Server chạy nhẹ: ~2% CPU, ~1,1 GB RAM.
  • Từ htop Tiến trình tốn CPU nhất là fly-fm-service (23,4%, thời gian CPU tích lũy 1h33) — không thuộc hệ thống Dcorp.
  • Từ htop Tiến trình tốn RAM nhất là SkyTab JposServer (Java, ~1,3 GB), lớn hơn cả SQL Server.
  • Suy luận Tính ngược từ 1.107 MB ≈ 7,0% → máy có khoảng 16 GB RAM. Tổng RAM của các tiến trình chính ~3,7 GB → còn dư nhiều.
  • Suy luận Với máy POS cấu hình thấp hơn (8 GB), cần giới hạn RAM cho SQL Server (memory.memorylimitmb hoặc --memory của Docker) và heap Java của SkyTab (-Xmx).
  • Thiếu Ảnh chụp tại thời điểm idle, chưa có số liệu khi đang bán hàng giờ cao điểm, load average và thời gian khởi động máy.
4 điểm chặn — nguyên nhân khả dĩ và hướng xử lý
Nguyên nhân dưới đây là giả thuyết kỹ thuật để KT kiểm tra, chưa được xác nhận trên máy test.
1. CRM không kết nối được SQL Server (Docker)Ưu tiên cao
Nguyên nhân khả dĩ (xếp theo khả năng)
  • Cao Driver cũ trong Wine (SQLOLEDB / SQL Native Client) chỉ dùng TLS 1.0/1.1, trong khi SQL Server trên Linux mặc định chỉ nhận TLS 1.2.
  • Trung bình Wine thiếu thành phần MDAC / OLE DB / ODBC driver.
  • Trung bình Port 1433 chưa publish ra host, hoặc firewall chặn.
  • Đã loại Tên instance / SQL Browser và Windows Authentication — mô hình khách hàng kết nối qua IP:port với tài khoản SQL.
Hướng xử lý
  • Test từ Linux bằng sqlcmd -S <IP>,1433, sau đó từ Wine bằng file .udl trong đúng prefix của CRM.
  • Xác nhận nguyên nhân TLS: tạm đặt mssql-conf set network.tlsprotocols 1.0,1.1,1.2 trên môi trường test rồi kết nối lại. Không giữ cấu hình này cho production.
  • Xử lý gốc: cài MS OLE DB Driver 18/19 hoặc ODBC 18 trong Wine, đổi chuỗi kết nối CRM sang driver mới, trả TLS về 1.2.
  • Ghi lại chính xác thông báo lỗi CRM để gửi UCS nếu vẫn không được.
Dự đoán khả năng xử lý CRM theo mô hình khách hàng (đánh giá chủ quan)

Mô hình chuẩn tại khách hàng: CRM App Server và MSSQL Server nằm trên 2 VM độc lập, kết nối qua IP:port. Hướng test giữ toàn bộ trên mã nguồn mở: VM MSSQL chạy Ubuntu 22.04 + SQL Server 2022 native; VM CRM App Server chạy Linux + Wine.

2. Ref / Mid / Rep chạy dạng Windows Service lỗi 1053Ưu tiên cao
Ý nghĩa và nguyên nhân khả dĩ
  • Lỗi 1053 = dịch vụ không phản hồi lệnh khởi động kịp thời.
  • Trình quản lý service của Wine không tương thích đầy đủ với service Windows của r_keeper.
  • Hệ quả: server chỉ chạy khi có người đăng nhập desktop, không tự lên sau khi mất điện / khởi động lại.
Hướng xử lý
  • Không dùng Windows Service trong Wine; tạo systemd unit trên Linux gọi wine refsrv.exe ở chế độ desktop, có Restart=always.
  • Hoặc tự động đăng nhập user pos và đưa vào autostart của phiên Fly.
  • Tham chiếu cách UCS mô tả trong tài liệu "Установка r_keeper 7 на Linux".
  • Test kịch bản rút điện → khởi động lại → server tự lên.
3. Máy in cổng COM chưa in đượcƯu tiên trung bình
Nguyên nhân khả dĩ
  • Chưa map cổng COM của Wine sang thiết bị Linux (~/.wine/dosdevices/com1 → /dev/ttyS0 hoặc /dev/ttyUSB0).
  • User pos chưa thuộc nhóm dialout → không có quyền mở cổng serial.
  • Sai tốc độ baud / tham số cổng so với cấu hình trong r_keeper.
Hướng xử lý
  • Kiểm tra cổng nhận diện: dmesg | grep tty.
  • Thêm quyền: usermod -aG dialout pos, đăng nhập lại.
  • Tạo symlink COM trong dosdevices, test in thẳng từ Linux trước (echo test > /dev/ttyS0).
  • Thống kê số cửa hàng còn dùng máy in COM để quyết định có cần giải quyết hay thay máy in.
4. SkyGuestScreen lỗi WPF / .NET runtime qua WineƯu tiên trung bình
Nguyên nhân khả dĩ
  • WPF dựa trên DirectX; Wine (và wine-mono mặc định) hỗ trợ WPF không đầy đủ.
  • Thiếu .NET Framework bản Microsoft trong prefix Wine.
Hướng xử lý
  • Thử prefix Wine riêng, cài dotnet48 + d3dcompiler_47 qua winetricks.
  • Thử tắt tăng tốc phần cứng WPF (registry DisableHWAcceleration).
  • Dài hạn: đề xuất bản GuestScreen dạng web / Linux native — vì SkyGuestScreen là sản phẩm Dcorp nên có thể chủ động.
Vấn đề phụ
  • fly-fm-service 23,4% CPU: tắt dịch vụ file manager / indexing trên máy POS, hoặc dùng phiên kiosk tối giản.
  • pulseaudio chạy 2 tiến trình, CPU tích lũy cao → kiểm tra, tắt nếu máy POS không dùng âm thanh.
  • Wine bản devel (/opt/wine-devel) → nên cố định một phiên bản Wine (stable) cho triển khai hàng loạt để tránh lỗi khi cập nhật.

Đang dùng trong test

Container chính thức Microsoft

Thư viện đóng gói sẵn, hiệu năng gần native. Image được Microsoft hỗ trợ; host Astra là vùng xám.

Cần kiểm tra khi bật ЗПС, Docker rootless, kernel hardened.

An toàn nhất về hỗ trợ

VM KVM, guest Ubuntu

SQL Server nằm trên cấu hình Microsoft hỗ trợ, ít chịu ảnh hưởng ЗПС/МКЦ.

Nặng hơn — phù hợp server trung tâm hơn là máy POS.

Không khuyến nghị

Cài gói Ubuntu trực tiếp

Phải tự xử lý OpenSSL / libldap, dễ hỏng khi cập nhật OS, phải ký binary nếu bật ЗПС.

Kết luận

Có thể vận hành hệ thống Dcorp trên Astra Linux về mặt kỹ thuật: lõi bán hàng, in hóa đơn (USB/Ethernet), SQL Server, Transporter và SkyTab đều đã chạy.

Chưa đủ điều kiện pilot tại cửa hàng cho đến khi xử lý xong CRM, chế độ chạy tự động của Ref/Mid/Rep, và có quyết định về máy in COM và SkyGuestScreen.

Rủi ro hỗ trợ: cả Microsoft (SQL Server trên Astra) và UCS (r_keeper qua Wine với MSSQL) đều chưa có cam kết hỗ trợ cho tổ hợp này. Dcorp sẽ tự chịu trách nhiệm hỗ trợ tầng OS/Wine.
